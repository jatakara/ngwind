# PROJECT NEXUS — Defense

브라우저에서 바로 실행 가능한 의존성 없는 전략 디펜스 게임 MVP입니다.

## 실행
`index.html`을 최신 브라우저로 열면 됩니다. `rules.js`와 `wave.js`가 같은 폴더에 있어야 합니다. 별도 빌드/서버/계정이 필요하지 않습니다.

## 테스트
Node.js 18 이상에서 저장소 루트 기준 `node --test games/project-nexus/*.test.js` 또는 게임 폴더에서 `node --test *.test.js`를 실행합니다. 외부 패키지 설치는 필요하지 않습니다. PR에서는 `.github/workflows/project-nexus.yml`이 테스트를 실행하도록 구성했습니다. 브라우저 전체 플레이 및 실제 모바일 터치 테스트는 별도로 수행해야 합니다.

## 구현 완료
- 포인터/터치로 포탑 배치, 자원 차감
- 웨이브 적 생성 및 자동 타게팅/발사
- 비행 중인 투사체의 예상 피해량을 반영한 중복 사격 방지
- 점수, 보상, 기지 체력, 패배, 재시작\n- 패배 후 추가 피해·처치 보상 차단 및 해당 프레임의 전투 처리 즉시 중단
- 배치 좌표, 충돌, 자원 및 타게팅 규칙에 대한 Node 내장 테스트
- 외부 패키지나 외부 네트워크 호출 없음

## 구조와 트레이드오프
- `index.html`: UI, Canvas 렌더링 및 게임 루프 (MVP 단일 파일)
- `rules.js`: 브라우저 전역 객체와 CommonJS 양쪽에서 사용 가능한 게임 규칙
- `rules.test.js`: 순수 규칙 테스트, 별도 DOM 환경 불필요\n- `wave.js`: 웨이브 시작, 피해, 처치 보상, 클리어의 순수 상태 전이\n- `wave.test.js`: 웨이브/패배/재시작 경계조건 테스트
- **장점:** `file://` 오프라인 실행, 외부 의존성 0개, 빠른 검증.
- **한계/기술 부채:** 게임 루프와 UI가 아직 결합돼 있어 통합 테스트·확장에 불리함. 다음 단계에서 상태 전이/시간 진행을 별도 모듈로 분리할 것.

## 개발 로드맵
1. 렌더링/시뮬레이션 분리 및 브라우저 E2E 테스트 (웨이브 상태 전이는 분리 완료)
2. 적 종류, 포탑 업그레이드, 난이도 밸런스
3. 웨이브 보스 및 로그라이크 업그레이드 선택
4. 접근성, 실제 모바일 UX, 저장 기능
5. RL 실험환경과 연계 (게임 플레이와 별도 격리)

## 보안/확장성
초기에는 클라이언트 전용 오프라인 게임으로 서버 공격면 및 개인정보 수집이 없습니다. 서버 도입 시 점수 위변조 방지, 인증, 속도 제한, 개인정보 최소 수집이 필수입니다. 프레임별 O(N×M) 타게팅은 적/포탑 수 증가 시 공간 인덱스 도입을 검토합니다. `rules.js`는 배치와 타게팅에 대한 단일 진실 공급원(Single Source of Truth)으로 유지합니다.
